## 2026-11-11 — Part 1: live config apply
- `ghostty::Loaded::files` lists what a load depends on: both main-file names (so creating `config.ghostty` next to a legacy `config` is noticed), every include read, the theme file. `cmux_config::watch::Watched` stamps files (mtime and length, `None` while missing); `changed()` says whether any differs.
- `scale_loop` became `window_view/config_ctl.rs::config_loop` (1 s, `spawn_in` the window so it can set the background and blur). It stats on the UI thread: a few files, microseconds. A Ghostty change rebuilds `TermStyle` and hands it to every `WorkspaceView` and the Dock, down to `TerminalView::set_style` (`apply_to`, then notify); `window.set_background_appearance` follows (`TermStyle::background_appearance`, shared with `main.rs`); Linux blur is dropped or re-enabled by replacing `_blur`. A `config.toml` change applies `ui_scale` as before, then `clear_key_bindings` + `actions::bind` (which also resets the palette's `Hints`), then reloads `[[vault.agents]]`. Warnings go to stderr as at startup.
- Appearance (A3): `observe_window_appearance` reloads the Ghostty side when dark/light flips. Side effect: gpui on Linux learns the scheme from the portal asynchronously, so a window opened before the portal answered now corrects itself; before, a wrong first guess stuck.
- Deviation from plan A1: ui_scale used to be compared every tick; now it reloads only on a stamp change (same result, one stat instead of a read). Not watched: a missing optional include appearing later, or a new user theme shadowing a resources theme (code comment `shortcut:`).
- Check on KDE (dev build, `SHELL=/bin/sh`, `XDG_CONFIG_HOME`/`XDG_STATE_HOME` under `$XDG_RUNTIME_DIR` with copies of the owner's Ghostty file and `config.toml`, inherited `CMUX_*` cleared, `debug.shortcut.simulate`, active-window screenshots read by the agent): editing the Ghostty file by script (opacity 0.7→1, background #400040, `font-size = 18`, `palette = 1=#ffff00`) showed within 2 s: opaque purple fill, bigger font, red text drawn yellow in the running shell. Opacity back to 0.6 with blur on made the window translucent again, no blur error on stderr. A `light:…,dark:…` theme pair loaded (dark half picked). `config.toml` rewritten with `ui_scale = 1.4` and `splitRight = "ctrl+alt+j"`: chrome grew; Ctrl+Alt+J did nothing before and split right after; Super+D no longer split. The empty Dock repainted with the new background; a Dock terminal was not open (needs a click), so its `set_style` path ran only as code. Not checked: a real desktop light/dark flip (would change the owner's desktop), blur by eye.

## 2026-11-11 — Part 2: writers
- `cmux_config::ghostty::edit`: `main_file(env)`, `set(path, key, value)`, `set_all(path, &[(key, value)])`, pure `edit(text, changes)`, `theme_value(light, dark)`. Last line per key rewritten in place (keeps its CRLF/LF), new keys appended under one `# cmux-linux` line in the file's line ending, BOM kept, earlier `font-family` lines get `# `. `config-file`, keys with `=`/`#`/whitespace and values with newlines are refused (no line injection). First write per file per process copies `<file>.cmux-bak`.
- `cmux_config::ghostty::origin(env, key) -> Option<(PathBuf, line)>`: the user file/line whose value wins, for W2's "Set in <file>". The loader now finds its main file through `edit::main_file`.
- `cmux_config::write`: `set_ui_scale` (2 decimals), `set_keybinding(action, &[chord])` (`[]` → `"none"`, one → string, more → list), `reset_keybinding`, `set_auto_naming(enabled, Option<command>)` (None/blank removes `command`), `set_agents(&[Registration])` (`[[vault.agents]]` under an implicit `[vault]`; empty removes them; `name` written only when it differs from `id`). A `config.toml` that doesn't parse is reported (`InvalidData`) and never overwritten.
- Learned: `toml_edit`'s `insert` replaces the key with its comments; `put` writes through `get_mut` and keeps the value's trailing comment. Both files go through `write::replace_file`: temp + rename, permissions copied, a symlinked file (dotfile managers) written at its target.
- Deviation: adding `toml_edit` as a direct dep adds one edge to Cargo.lock (no new package, no version change), so this commit carries a one-line Cargo.lock change; `--locked` passes after it.
- Check (task 3): copied the owner's Ghostty and cmux-linux config to a scratch XDG dir, wrote all W3 keys plus a second `font-size` write and the four config.toml writers. `diff -u` shows only the changed/appended lines; the loader reads them back with no warnings; `ghostty +validate-config` (1.4.0) exits 0 on the result (and 1 on a deliberately bad value, so it does check). Only `cargo test/clippy/fmt -p cmux-config` were run here (vendor/ghostty not initialised in this worktree); the change is additive to cmux-config's API.

## 2026-11-12 — Part 3a: Settings window shell, controls, App and Terminal
- `cmux-app::settings` (S1–S3, S5, S8): `open()` focuses the existing window or opens a second gpui window (980×680, server decorations, `app_id` cmux-linux). `openSettings` = Super+, (DEFAULTS, remappable), palette "Settings…", and "Settings…" in the sidebar's blank-area menu. `WindowView` keeps the handle; its `on_release` removes the Settings window, so closing the main window still quits (gpui on Linux stops only when no window is left). In Settings, Super+Q quits, Super+W (`closeTab`) closes it, Up/Down move through the sidebar (cmux's list does the same).
- Sections: `Section` enum + `GROUPS` (General: App, Themes; Terminal; Agents & Automation; Keyboard & Advanced), Lucide icons settings/paintbrush/terminal/wand-sparkles/keyboard. Themes, Automation, Keyboard Shortcuts render a "Coming next." card; the second half adds a `render_*` per section, `FieldId` variants for its text fields and uses `toml_changed` (called from `config_ctl::reload_toml`) to re-read config.toml values.
- `settings/controls.rs`: `Colors` (from the terminal background via `chrome`), `header`, `card`, `row`, `note`, `toggle`, `stepper`, `segmented`, `slider` (track bounds from a `canvas`, drag handled by the view's root mouse listeners, value written on release), `dropdown_button`/`dropdown_list` (deferred + anchored, closes on click outside), `text_field` (the caller runs `rename.rs`'s `RenameState`; Enter, blur or a click elsewhere commits, Escape cancels).
- Values: the view holds a `Config` clone and applies its own changes with `Config::apply`, so rows update at once; Ghostty writes are queued per key and written together after 250 ms (`edit::set_all` on `edit::main_file`), and on window close. When the main window reloads (`set_style`) the rows show the loaded values unless a write is still queued. W2 note: `ghostty::origin` per key, shown in orange when the winning file is not the main file. Font list: families whose `M` and `i` advances match, scanned on a background thread on the first dropdown open (about 1.1 s in a debug build, 33 families here). ui_scale stepper 0.5–2.0 by 0.05, written at once through `write::set_ui_scale`; a value above 2.0 from the file only steps down.
- `debug.shortcut.simulate` now presses into the active window when that is not the main one (the Settings window), like a real key press; otherwise unchanged.
- Learned: gpui on Wayland ignores `TitlebarOptions::title` (KWin showed an empty caption), so the view calls `set_window_title`. KWin does not always focus a window opened by a synthetic key: once, the second Settings window opened unfocused, and a scripted Super+W went to the main window, closed its only tab and quit; real presses were not tried.
- Deviations: cmux puts Settings rows under its own `config.ghostty`; we write the user's file (plan W1). The Terminal card's note names that file. No search field (plan S2). Cursor style titles follow cmux (Block, Bar, Underline, Hollow).
- Check on KDE (dev build, `SHELL=/bin/sh`, `XDG_CONFIG_HOME`/`XDG_STATE_HOME` under `$XDG_RUNTIME_DIR` with copies of the owner's Ghostty file and config.toml plus a `config-file = extra` that sets `font-size`, inherited `CMUX_*` cleared): Super+, by `debug.shortcut.simulate` opened Settings on App (Interface Scale 115%); Down, Down showed Terminal with all nine rows, values from the file (70% opacity, blur on) and the "Set in …/extra" note on Font Size only. No pointer tool is installed, so the controls were not clicked: `ui_scale = 1.4` and `background-opacity = 0.95` were written through the same calls the controls make (`write::set_ui_scale`, `edit::set_all`), from a scratch crate. Within 2.5 s the open Settings window re-rendered at 140% with the slider at 95% (it only gets these through the main window's reload), and after Super+W closed Settings the main window showed the larger chrome and the near-opaque fill. `diff` showed only the two changed lines. A KWin script closing the main window by pid quit the app with Settings open (exit 0). Not checked: any mouse path (toggle, stepper, slider drag, segmented, dropdown, colour field typing), the 250 ms debounce in practice, the dropdown's popup layering inside the scrolling column.
