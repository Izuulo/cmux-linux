## Part 1: command palette (exit 1)

| | Decision | Why |
|---|---|---|
| P1 | Two bindings: `commandPalette` Super+Shift+P opens the list with the query `>`; `commandPaletteSwitcher` Super+P opens it empty (workspace switcher). A query starting with `>` lists commands, any other lists workspaces and the selected workspace's tabs. Pressing the same binding again closes it, the other one switches mode. Escape or a click outside closes it; focus goes back to what had it. | cv:5188, :10243–10314. KDE takes Meta+P for display switching by default; the binding is remappable and the README says so. |
| P2 | Keys: Up/Down and Ctrl+P/Ctrl+N move, clamped (no wrap); Enter runs; Backspace edits. Text entry reuses `rename.rs`'s `RenameKey` state machine. Mouse hover highlights, click runs. | `CommandPaletteShortcutRouting.swift`, cv:10018. |
| P3 | Entries: one table `PALETTE: &[(&str action, &str title)]` in `cmux-app::actions` with a title for every `DEFAULTS` action except the two numbered ones; a test fails if a `DEFAULTS` action is missing. The numbered ones are reached through the switcher (each workspace, each tab of the selected workspace). The hint is the action's first bound chord from `Keybindings`, shown as `Super+Shift+P`. Entries with no handler in the current focus are still listed. | Exit 1 by construction. cmux gates by `when`/`enablement`; we have no such state yet. |
| P4 | Running: close, give focus back, then `window.dispatch_action(action_for(binding))`, so copy/paste and pane actions reach the terminal that had focus. | cmux's "dismiss before run" list (`ContentView+CommandPalettePresentation.swift:3`), for every entry: simpler, and our actions are focus-routed. |
| P5 | Matching is pure, `cmux-core::palette::score(query, texts) -> Option<i32>` and `rank`: query trimmed, lowercased, split on spaces; per token the best of exact 8000, whole prefix 6800−(len diff), word prefix 5600−8·wordStart−6·(wordLen−tokLen)−(candLen−wordLen), substring 4200+boundary bonus (220 start, 180 after `space - _ / . :`)−9·pos−(len diff), and for tokens ≤3 chars a subsequence score (fm:994); a token that matches nothing drops the entry; tokens sum. Texts searched: title then keywords. Ties: table order. | fm:495–551. Not ported: typo, initialism, stitched prefixes, title bonus, recency boost, match highlighting, nucleo. |
| P6 | Visuals (`window_view/palette.rs`, chrome colours): width `min(560, max(340, window−260))`, centred, 40 px from top, radius 8, shadow black 24 % r10 y5; field 13 px, padding 9×7, divider; rows 24 px, padding 9×2, list max 450 px, selected row accent at 12 %, hovered 4 %; hint 11 px medium in a 4 px rounded box at 8 %. Placeholders "Type a command" / "Search workspaces and surfaces"; empty "No commands match your search." / "No workspaces match your search." Titles only, no subtitles. | `CommandPaletteOverlay.swift`, cv:3983–4043, :5214–5865. |

Tasks: 1 `cmux-core::palette` scoring with tests (orders like cmux's on a handful of cases); 2 the table, its sync test, the two bindings in `cmux-config` and `actions.rs`; 3 the overlay view, keys, run and focus return; 4 switcher rows; 5 check on KDE: `debug.shortcut.simulate` opens it, a screenshot, and a script that runs each table entry through the palette and sees the action happen (or at least the overlay close without error for focus-only actions).

## Part 2: `cmux.json` custom commands (exit 2)

| | Decision | Why |
|---|---|---|
| C1 | Files: the project file is found by walking up from the selected workspace's active cwd, `.cmux/cmux.json` before `cmux.json` in each directory, first hit wins; the global file is `~/.config/cmux-linux/cmux.json`. Commands merge by name, project first. Read when the palette opens (no file watch). | cc:2109, :2249. Our config dir, not `~/.config/cmux/`. Reading on open keeps it fresh without a watcher. |
| C2 | Schema, only `commands`: `name` (required), `description`, `keywords`, and exactly one of `command` or `workspace`; `restart` (`new`, `ignore`, `recreate`, `confirm`; default `new`); `confirm`. `workspace`: `name` (default the command's), `cwd`, `env`, `layout` (split `{direction, split?, children:[2]}`, clamped 0.1–0.9; pane `{pane:{surfaces:[{type:"terminal", name?, command?, cwd?, env?, focus?}]}}`). Other top-level keys and `browser` surfaces are ignored with a warning. Parsed with serde_json in `cmux-config::commands` (new dependency there; serde_json is already in the tree). | cc:1578–1640, `CmuxWorkspaceDefinition.swift:3`. No `actions`, `packs`, `color`, `setup`, `ui`. |
| C3 | Palette rows "Custom: <name>", keywords searched; a file that fails to parse shows a row "cmux.json: <error>" that does nothing; the other file still loads. | cc:2810–2830. |
| C4 | Run, plain `command`: types `command` + Enter into the focused terminal of the selected workspace (`send_scripted`). `workspace`: builds the layout through M10's `Layout::from_shape`, each terminal started in its `cwd` (`~` home, absolute, else joined to the selected workspace's cwd) with its `env` (our `CMUX_*` win), then types its `command`. `restart` compares against an existing workspace with that title. | ce:16–76. Relative cwd base as cmux (not the file's folder). |
| C5 | Trust: commands from the global file run at once unless `confirm: true`. Commands from a project file ask first (`window.prompt`: "This project action comes from <path>. It will run: <command>", Run / Trust and Run / Cancel). Trust is kept per (file path, command text or workspace JSON) in `~/.local/state/cmux-linux/trusted-commands.json`; a changed command asks again; `confirm: true` always asks. | ce:376–440. A cloned repo must not run code on one click. |

Tasks: 1 `cmux-config::commands` parse, lookup and merge with tests (fixtures in a temp dir); 2 palette rows and the error row; 3 plain run and trust prompt with its file; 4 `workspace` runs (layout, cwd, env, restart); 5 check on KDE: a temp project with a plain and a workspace command, cd there, open the palette by script, run both, see the typed line and the new workspace.

## Part 3: `cmux ssh` (exit 3)

| | Decision | Why |
|---|---|---|
| S1 | `cmux ssh <dest> [--port N] [--identity PATH] [--name TITLE] [--command TEXT] [--ssh-option OPT]… [--focus true\|false]`. A destination starting with `-` is rejected. The CLI builds the argv `ssh -tt -o ControlMaster=auto -o ControlPath=~/.local/state/cmux-linux/ssh/%C -o ControlPersist=600 -o StrictHostKeyChecking=accept-new -o ServerAliveInterval=20 -o ServerAliveCountMax=2 -o SetEnv=COLORTERM=truecolor [-p N] [-i PATH] [-o OPT]… <dest>` (directory made 0700) and sends `workspace.create` with a new `remote: [argv…]` param; the title defaults to `<dest>`. `--command` is typed into the first terminal once it opens. | cs:14437–14540 and the help text. No cmux-tui daemon, cmuxd-remote, relay, mosh, `--transport`, `-A`, trailing `-- cmd`, stored passwords. A password or host-key prompt shows in the first terminal; later splits reuse its master. |
| S2 | The workspace keeps the argv; every terminal it starts (first, splits, tabs) runs that argv as its PTY program instead of the local shell, with our `CMUX_*` variables (they don't cross ssh). When ssh exits the surface closes, as with a shell. M10's `session.json` saves the argv per workspace, so a restore reconnects. | cmux's `terminal_startup_command` per workspace (`Workspace.swift:8184`). No reconnect loop (cmux's wrapper retries): a dropped link closes the pane. |
| S3 | Sidebar for a remote workspace: the host as the branch line's prefix; cwd from the remote shell's OSC 7 when it sends one (`osc_cwd`), else none; every 5 s one `ssh -o ControlPath=… -o BatchMode=yes -o ControlMaster=no <dest> sh -c '<probe>'` that prints the git branch in that cwd and `ss -ltnpH`; ports are those with a `users:` field (processes the remote user owns). No PR line. Skipped while no master is up (`ssh -O check`). No `/proc` reads for remote terminals. | cmux gets cwd/branch through injected shell integration and a relay; we don't inject. Ports as cmux's `ss` scan (`+PortScanScripts.swift`), filtered by owner instead of TTY. Deviation. |
| S4 | Dropping image files (png, jpg, jpeg, gif, webp, any case) on a terminal of a remote workspace uploads them: one `ssh … 'mkdir -p -m700 ~/.cache/cmux/paste && printf %s "$HOME"'`, then `scp -q -o ControlPath=… -o BatchMode=yes -o ConnectTimeout=6 <local> <dest>:<home>/.cache/cmux/paste/cmux-paste-<random>.<ext>` and `chmod 600` on it, then types the shell-escaped remote paths space-joined, no newline. On failure the scp stderr goes to a notification. Other drops (non-images, local workspaces) type the local paths, as Ghostty. Runs on the background executor. | sd:129–320, `TerminalImageTransfer.swift:516`. Not ported: per-session folders and the 24 h / 200 MB pruning, detecting a hand-typed `ssh` in a local pane. |

Tasks: 1 CLI `cmux ssh` in `cmux-ipc::cli::ssh` with argv tests; 2 `remote` on `workspace.create`, the workspace's argv, terminals spawning it; 3 save/restore of the argv; 4 sidebar probe (pure parser for the probe output in `cmux-meta::remote` with tests, poller in the app); 5 file drop and scp upload; 6 check on KDE against `localhost` (sshd is running here): `cmux ssh localhost`, split, see both remote shells and the sidebar ports of a `python -m http.server` started remotely, drop a PNG and see the path typed; then the owner against a real host.

## Deferred (with reason)

- Palette: recency boost, match highlighting, typo/initialism matching, `when`/`enablement` gates, subtitles, rename modes: polish beyond exit 1.
- `cmux.json` `actions`, `packs`, keybindings for custom commands, file watching, `cmux reload-config`: nightly features in cmux or not needed when reading on open.
- SSH reconnect loop, remote shell integration (cwd/branch without OSC 7), remote PR line, mosh, cmux's remote daemons: each a project of its own; the spec asks for metadata "where available".
- Browser surfaces in `cmux.json` layouts: M13.
