## 2026-11-11 — Part 3: `cmux ssh`
- Part 2 review fixes (own commit): trust is keyed on the project file's path as found, not canonical, so a symlinked `cmux.json` doesn't borrow its target's trust (tested); the prompt says "This action" for a global `confirm: true` command; a non-boolean surface `focus` fails the file like `confirm`.
- Built: `cmux ssh <dest> [--port] [--identity] [--name] [--command] [--ssh-option]… [--focus] [--window]` (`cmux-ipc::ssh` argv, `cli/ssh.rs`, help); `workspace.create` takes `remote: [argv]`; `WorkspaceView.remote` starts every terminal (first, splits, tabs, restore) with `Session::argv_command(argv)` (same TERM/COLORTERM and `CMUX_*` rules as the shell); `session.json` gets an additive `remote` per workspace (absent in older files = local). `cmux-meta::remote`: connection options from the argv, `ssh -O check`, the probe, `parse_probe`, the upload argvs, quoting. App: `remote_loop` every 5 s; `meta_inputs` skips remote workspaces (no `/proc`); `TerminalView::file_drop`.
- Learned: ssh keeps the first value given for an option, so the probe and uploads put `BatchMode=yes`/`ControlMaster=no` before the workspace's own `-o` list. `%C` hashes the port, so scp must get the same port: `-p N` becomes `-o Port=N`, which ssh and scp both take. Login startup files can print on a non-interactive ssh, so the upload takes `$HOME` from the last output line (cmux uses a marker line for the same reason). Fish reads `\` inside single quotes, so the probe script has none.
- Deviations from the plan: the ControlPath is the absolute state dir (`$XDG_STATE_HOME/cmux-linux/ssh/%C`, which is the plan's `~/.local/state/…` by default) so it matches the directory the CLI makes. The probe also prints `$HOME` (for `~/…` in the sidebar); a detached `HEAD` shows no branch. The upload's scp also carries the workspace's options (port, identity, `-o`s), not just ControlPath, so it reaches the same master. A drop with images and other files on a remote terminal uploads the images and types the others' local paths, in drop order. Paths are typed single-quoted when needed (Ghostty backslash-escapes); same effect. `--focus` defaults to true for `cmux ssh` (cmux switches unless `--no-focus`).
- Deviations from the Swift app: as the plan (no daemon, relay, mosh, reconnect loop, agent forwarding, per-session paste dirs, pruning). Port links in a remote row still open `http://localhost:<port>`, which is not forwarded.
- Check on KDE (dev build, `SHELL=/bin/sh`, own `XDG_STATE_HOME`/`XDG_CONFIG_HOME` under `$XDG_RUNTIME_DIR`, inherited `CMUX_*` cleared): no key auth to localhost here (the brief forbids adding one), so a fake `ssh` on the app's `PATH` logged its argv and ran a local `sh -i` for `-tt`, `sh -c "<remote command>"` otherwise, `exit 0` for `-O check`; a fake `scp` copied. `cmux ssh dev@localhost --command …` made workspace "dev@localhost" with the plan's argv (ControlPath dir 0700) and typed the command; `new-split right` spawned the same argv; `python3 -m http.server 8765` in the split and an OSC 7 to a git repo gave the row "localhost · feat · <repo>" and `:8765` among the ports (the fake's `ss` is local, so the owner's other listeners showed too). `session.json` carried `remote`; after Super+Q and relaunch both panes ran ssh again and the row showed "localhost". `exit` in a remote pane closed it. `remote::poll` and `remote::upload` also run end to end against the fake ssh/scp in `cmux-meta/tests/remote_fake_ssh.rs` (branch, own port, file copied to a fresh `cmux-paste-*.png`, modes 600/700).
- Not checked: a real host (owner: `cmux ssh <host>`, split, a password or host-key prompt in the first pane, sidebar ports of a remote server, drop a PNG and see the remote path typed); the drop itself (no scriptable drag source on Wayland), so `file_drop` and the failure notification are unexercised in the app.
- Fixes after review:
  - `--command` now waits for the master: the app polls `ssh -O check` every 250 ms, for up to 2 minutes, then types it; on timeout it posts "Command not run". So it never lands in a password or host-key prompt. Checked on KDE with a fake ssh whose `-O check` fails until a flag file exists: nothing was typed while the check failed, and the command ran within 2 s of the flag file appearing.
  - A remote row's port links open `http://<host>:<port>`. The host comes from the destination, bracketed if it is IPv6. An ssh-config alias the browser can't resolve won't open.
  - One parser (`remote::argv_from_json`) for `remote` on the socket and in `session.json`. It needs a non-empty string array starting with `ssh`. The socket rejects anything else; `session.json` restores it as a local workspace.
  - The CLI rejects `ssh://` destinations.
  - The remote poller runs once right away.
  - `--window` is in the usage line.
  - The paste dir is `chmod 700`'d after mkdir.
  - The drop text is built by the pure `remote::drop_text` (tested).
