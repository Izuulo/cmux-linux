# M2 research: gpui 0.2.2, Zed split/tab reference, PTY shutdown

Read-only research for the M2 plan. Citations: `gpui-0.2.2/src/...` is the registry crate;
`zed@69e2130 <path>` is Zed at the commit matching gpui 0.2.2 (GPL-3.0-or-later, Copyright Zed

UNVERIFIED. No code was written; the one throwaway experiment is noted in section 3.

## 1. gpui 0.2.2 APIs

### 1.1 Flex layout of nested splits

- `div()` defaults to `Display::Block` (style.rs `impl Default for Style`), so a split container needs
  `.flex()` plus `.flex_row()` / `.flex_col()` (`gpui-0.2.2/src/styled.rs:44,137,151`). `flex_row` alone does not turn flex on.
- Sizing: `flex_1()` = grow 1, shrink 1, basis `relative(0)` (styled.rs:165); `flex_auto`, `flex_none`,
  `flex_basis(impl Into<Length>)` (:200), `flex_grow()` (:207, fixed to 1), `flex_shrink_0()` (:221).
  `relative(f32) -> DefiniteLength` (geometry.rs:3567) is a fraction of the parent.
- Weighted children (ratios): there is no `flex_grow(f32)` setter, but `Styled::style(&mut self) -> &mut StyleRefinement`
  (styled.rs:23) is public: `d.style().flex_grow = Some(w)`. Pattern: each child `flex_basis(relative(0.))`,
  `flex_grow = ratio`, `flex_shrink = 1`, `overflow_hidden()`, `min_w`/`min_h` (generated by the prefix macro,
  gpui-macros-0.2.2/src/styles.rs:921,931; `min_w_0` name UNVERIFIED). Children of a flex row need a min size of 0 or a wide terminal child keeps the pane from shrinking.
- M1's `TerminalView::render` is `div().size_full()...` (terminal_view.rs:353) and `TerminalElement::request_layout` asks for
  100%x100% (terminal_element.rs:124-127); both work as a flex child if the wrapper sets a definite basis/size.
- A parent view embeds a child view with `.child(entity)`: `impl<V: 'static + Render> IntoElement for Entity<V>` (view.rs:296).
  Children are re-rendered every frame unless `.cached(style)` is used (view.rs:103); not needed for M2.
- Getting child bounds from plain divs: `Div::on_children_prepainted(impl Fn(Vec<Bounds<Pixels>>, &mut Window, &mut App))`
  (div.rs:1243). Needed for directional focus and divider-drag maths.
- Pixel-exact alternative: a custom `Element` doing `child.layout_as_root(size.into(), window, cx)` then
  `child.prepaint_at(origin, window, cx)` (element.rs:619,630), which is what Zed does (section 2). Exact snapped bounds, and the bounds are known without a second pass.
- Rounding of fractional taffy sizes: UNVERIFIED (Zed rounds explicitly, pane_group.rs `.map(|d| d.round())`). M1's prepaint already snaps the grid origin to device pixels and floors cols/rows (terminal_element.rs:169-181).

### 1.2 Divider dragging

Two workable routes.

**A. Zed-style custom element (recommended; section 2).** No `on_drag`. In prepaint insert a hitbox
`window.insert_hitbox(bounds, HitboxBehavior::BlockMouse)` (window.rs:3305; `HitboxBehavior` window.rs:570); in paint register
`window.on_mouse_event(|e: &MouseDownEvent/MouseMoveEvent/MouseUpEvent, phase, window, cx| ...)` (window.rs:3421), keep
the dragged index in `window.with_element_state::<Rc<RefCell<Option<usize>>>, _>(global_id, ...)` (window.rs:2628), and set
the cursor with `window.set_cursor_style(CursorStyle::ResizeColumn|ResizeRow, &hitbox)` (window.rs:2351) or, while
dragging, `window.set_window_cursor_style(..)` (window.rs:2363) so the cursor survives leaving the 4px hitbox.
`CursorStyle::{ResizeLeftRight, ResizeUpDown, ResizeColumn, ResizeRow}` exist (platform.rs:1442-1470). Handlers run in
bubble phase in reverse registration order (window.rs:3703-3712), so the axis element, painted after its children, runs first and its
`cx.stop_propagation()` keeps terminals from seeing the move. Mouse events keep arriving outside the window while a button is held on Wayland: UNVERIFIED.

**B. Div + gpui drag API.** Needs a stateful element: `div().id("divider").cursor_col_resize()` (styles.rs:290 `cursor_col_resize`,
:297 `cursor_row_resize`, :262 `cursor_ew_resize`), then:
- `.on_drag(value: T, |&T, Point<Pixels>, &mut Window, &mut App| -> Entity<W: Render>)` (StatefulInteractiveElement, div.rs:1132; imperative div.rs:499). The
  preview entity can be `cx.new(|_| EmptyView)` (view.rs:367). The drag only starts after the pointer moves more than 2 px (`DRAG_THRESHOLD`, div.rs:47,2159).
  The divider's `mouse_cursor` base style is copied into `AnyDrag.cursor_style` (div.rs:2082) and re-applied to every element while dragging (div.rs:2538).
- `.on_drag_move::<T>(|&DragMoveEvent<T>, &mut Window, &mut App|)` on the container (div.rs:282,818): fires for every mouse move
  while a drag of type `T` is active, even outside the element, capture phase (div.rs:289). `DragMoveEvent { event: MouseMoveEvent, bounds: Bounds<Pixels> /* the container's */ }` (div.rs:62); `drag(cx)` returns `&T`.
  New ratio = `(event.position - bounds.origin).along(axis) / bounds.size.along(axis)`.
- The drag is cleared after the mouse-up listeners run (window.rs:3716-3727); a double-click reset can use `.on_click` with `ClickEvent::click_count()` (Zed pane.rs `event.click_count() == 2`).
- Drawback: ordinary listeners still run during a drag (nothing suppresses them; only hover styles are off, div.rs:2498-2509). M1's `mouse_move`/`mouse_down` on terminals
  (mouse.rs:115,155) would send mouse reports to a TUI while the user resizes. Guard with `cx.has_active_drag()` (app.rs:1939) in the terminal mouse handlers.

### 1.3 Tab drag-reorder

All on a stateful div (`.id(...)`), pattern from Zed `pane.rs:2641-2686`:
- Source: `.on_drag(DraggedTab { pane: WeakEntity<..>, ix, .. }, |tab, _offset, _window, cx| cx.new(|_| tab.clone()))`. The payload must be `'static`; the second value must be an `Entity<impl Render>` that draws the ghost
  (`DraggedTab` implements `Render`, pane.rs:4189). gpui paints it at `mouse_position - cursor_offset` as a root element (window.rs:2055-2060,2078).
  Use `WeakEntity` in the payload to avoid keeping a closed pane alive.
- Target styling: `.drag_over::<DraggedTab>(|style: StyleRefinement, dragged: &DraggedTab, window, cx| style.bg(..).border_l_2())` (div.rs:938; applied when `hitbox.is_hovered` and `can_drop`, div.rs:2530-2537).
  Zed puts the border on the side the tab will land (`ix < dragged.ix` left, `ix > dragged.ix` right). `group_drag_over::<T>(group, f)` (div.rs:957) styles by group hover.
- Drop: `.on_drop::<DraggedTab>(|dragged: &DraggedTab, window, cx| ...)` (div.rs:976; imperative :462). It fires on mouse-up when the hitbox is hovered and the type matches, takes the drag, calls `window.refresh()` and stops propagation (div.rs:2090-2120). Optional `.can_drop(|&dyn Any, window, cx| bool)` (div.rs:986; imperative :473).
- Also add a trailing drop target (a flex-grow empty div after the tabs, Zed pane.rs:3132-3150) so dropping after the last tab works.
- Cancel with Escape: `cx.stop_active_drag(window)` (app.rs:1949; Zed pane.rs:3828-3833).
- Overflow: `h_flex().id(..).overflow_x_scroll().track_scroll(&ScrollHandle)` and `scroll_handle.scroll_to_item(ix)` for the active tab (Zed pane.rs:3125, 1324).
- Edge-drop-to-split (Zed `handle_drag_move`, pane.rs:3195-3250): `on_drag_move::<DraggedTab>` on the pane body computes the nearest edge from `event.bounds` and cursor. Optional for M2.

### 1.4 Focus with multiple child views

- `Context::focus_handle(&self) -> FocusHandle` (app.rs:2029); expose via `impl Focusable for V { fn focus_handle(&self, &App) }` (window.rs:440). `Entity<V: Focusable>` is `Focusable` too (window.rs:445).
- Render side: `div().track_focus(&handle)` (div.rs:616) puts the handle in the dispatch tree at that element. Nesting is by element nesting, so a pane `div().track_focus(&pane_handle)` that contains a terminal view whose div tracks its own handle gives a focus path pane -> terminal.
- Moving focus: `window.focus(&handle)` (window.rs:1386; no-op if already focused), `handle.focus(window)` (:340), `cx.focus_view(&entity, window)` (context.rs:287), `window.blur()`, `window.focus_next()/focus_prev()` (:1413,1424, tab-stop based, not needed).
- Queries: `window.focused(cx) -> Option<FocusHandle>` (window.rs:1380); `handle.is_focused(window)` (:345, exact); `handle.contains_focused(window, cx)` (:351, handle or any descendant, uses the last rendered frame);
  `handle.within_focused(window, cx)` (:357).
- Events (all hold the view weakly via `weak_entity()`, context.rs:532-640): `cx.on_focus(&h, window, f)` (exact gain), `cx.on_focus_in(&h, ..)` (gain by h or a descendant; not fired if focus moves within h), `cx.on_blur(&h, ..)` (exact loss),
  `cx.on_focus_out(&h, .., |view, FocusOutEvent, window, cx|)` (h or descendant lost it), `cx.on_focus_lost(window, f)` (nothing focused any more, context.rs:608; fires when the focused element vanished from the tree, window.rs:1950). Window-level versions: `window.on_focus_in/out` (window.rs:3481,3501). Each returns a `Subscription`; keep it in a field (M1 does, terminal_view.rs:157-160).
- Recommended: the pane wrapper owns a handle that wraps its terminal; `cx.on_focus_in(&pane_handle, ..)` marks the active pane (Zed does this, pane.rs:490-491, `focus_in` :595). A focus click works already: M1's `mouse_down` calls `window.focus(&self.focus)` (mouse.rs:121).
- Style hooks: `.focus(|s| ..)` (div.rs:1020), `.in_focus(|s| ..)` (:1030) for an active-pane border without custom code.
- When a tab or pane is removed while it had focus, the window ends up with no focus: dispatch falls back to the root node (window.rs:3982 `focus_node_id_in_rendered_frame` -> root), so
  keybindings only reach root-level handlers. Always `window.focus(next)` on close and add a `cx.on_focus_lost` fallback.
- M1's TerminalView only paints its IME handler when its handle is focused (`window.handle_input` checks `is_focused`, window.rs:3408), so hidden/background tabs are safe.

### 1.5 Actions and keymaps

- Define: `gpui::actions!(cmux, [SplitRight, SplitDown, ...])` (action.rs:24) makes unit structs with name `cmux::SplitRight`, registered at link time (inventory). Data-carrying actions: `#[derive(Clone, PartialEq, serde::Deserialize, schemars::JsonSchema, gpui::Action)] #[action(namespace = cmux)]`, or `#[action(no_json)]` to skip serde/schemars (action.rs:42-100). Unit-struct `build` ignores JSON (gpui-macros-0.2.2/src/derive_action.rs:121-127), so `actions!` needs no serde/schemars.
- Bind: `cx.bind_keys([KeyBinding::new("super-d", SplitRight, Some("Terminal"))])` (app.rs:1677, binding.rs:33; panics on a parse error). Keystroke syntax: `ctrl-/alt-/shift-/cmd-|super-|win-/fn-`, lowercase key, `secondary-` = ctrl on Linux; chords are space-separated (binding.rs:48-66, keystroke.rs:120-190). `super-` and M1's `chord()` strings (keys.rs:22) use the same spelling.
- Config-driven (what M2 needs): parse each TOML entry to `(keystrokes: String, action_name: String, context: Option<String>)`, then
  `cx.build_action("cmux::SplitRight", None) -> Result<Box<dyn Action>, ActionBuildError>` (app.rs:1725) and
  `KeyBinding::load(&keystrokes, action, context.map(|c| Rc::new(KeyBindingContextPredicate::parse(&c)?)), false, None, cx.keyboard_mapper().as_ref()) -> Result<KeyBinding, InvalidKeystrokeError>` (binding.rs:48; `keyboard_mapper` app.rs:728). That validates without panicking and lets us surface config warnings. `cx.all_action_names()` (app.rs:1735) lists valid names for error messages. Action types are only registered if the defining crate is linked (our lib crate is).
- Runtime rebind: `cx.clear_key_bindings()` (app.rs:1683) then `cx.bind_keys(defaults_then_user)` (both queue `RefreshWindows`; `Keymap::add_bindings/clear` bump `version`, keymap.rs:44,62). Re-run on config reload. Disable a default: bind `gpui::NoAction` to the same keystroke after the default (keymap.rs:173-187; a `NoAction` without `meta` counts as a user binding and ends the match).
- Precedence (keymap.rs:142-170): among matching bindings, sort by context depth descending, then later-added first. A binding with no context scores the full stack depth, so it beats context-specific bindings on the same keystroke (UNVERIFIED in practice; follows from `binding_enabled`, keymap.rs:209-215 and the `test_keymap` unit test in keymap.rs, which expects `Some(0)` for an empty stack). Keep one context scheme (all bindings contextless, or all under named contexts) to avoid surprises. Add defaults first, user entries after.
- Contexts: `div().key_context("Terminal")` (div.rs:658; M1 already sets "Terminal", terminal_view.rs:358); a `KeyContext` can hold several identifiers/`key=value` (`KeyContext::new_with_defaults`, Zed pane.rs:3685-3688). Context stack = key_context of every dispatch-tree node on the path root -> focused node; predicate syntax `a && b`, `!a`, `a == b`, `a > b` (descendant).
- Multi-keystroke bindings are supported but cost: the first stroke becomes pending and is swallowed for up to 1 s (window.rs:3803-3826; replay at :3945-3980), so a chord prefix like `ctrl-b` would delay normal terminal typing. Do not ship chord defaults; cmux's table is single-chord (check spec when writing the table).
- Handlers: `div.on_action(cx.listener(|this, _: &SplitRight, window, cx| ..))` (div.rs:854; closure type `Fn(&A, &mut Window, &mut App)`), `.capture_action::<A>` (div.rs:842; capture phase), `cx.on_action(|a: &A, cx|)` global (app.rs:1696, runs last), `window.on_action(TypeId, ..)` low level (window.rs:4346). Programmatic dispatch: `window.dispatch_action(Box<dyn Action>, cx)` (window.rs:1476) or `handle.dispatch_action(&action, window, cx)` (:367) for menus and the future socket (M5).
  Bound-key lookup for display: `window.bindings_for_action(&action)` (window.rs:4223).

### 1.6 Propagation order (key to action handler)

`Window::dispatch_key_event` (window.rs:3730-3835):
1. Dispatch path = root -> element that tracks the focused handle, built from the element tree, not the entity tree (`dispatch_path`, key_dispatch.rs:550). A parent view's div that wraps a child view is on the path.
2. Keystroke interceptors, then the keymap lookup against `context_stack` (window.rs:3779-3790).
3. If a binding matched: `dispatch_action_on_node(focused node, action)` for each matched binding in order (window.rs:3834-3846; :3992-4090): global capture listeners, then node capture listeners root -> focused, then node bubble listeners **focused -> root**, then global bubble listeners. In the bubble phase gpui sets `propagate_event = false` before calling a handler (window.rs:4056), so the first handler on the way up consumes the action unless it calls `cx.propagate()` (app.rs:1720). If no handler stops it, the next matched binding is tried, then
4. `finish_dispatch_key_event` (window.rs:3848,3852): `on_key_down`/`on_key_up` listeners run capture root -> focus then bubble focus -> root (window.rs:3878-3907); a key-down handler that does nothing lets the keystroke fall through to IME text input (replay path, window.rs:3976, M1 comment terminal_view.rs:281-284).

Consequences:
- A workspace-level div with `.on_action(...)` receives split/tab/focus actions whichever terminal is focused. Pane-local actions (new tab) can sit on the pane div; the nearest handler wins.
- A terminal-level `Copy` handler can decline: call `cx.propagate()` inside it (no selection), and because no ancestor handles `Copy`, the keystroke falls to the terminal's `key_down` and reaches the PTY. That delivers STATUS.md's "Ctrl+Shift+C with no selection passes through".
- With nothing focused, dispatch uses the root node only (see 1.4).
- Actions fire on key repeat too (`dispatch_key_event` does not look at `is_held`), so holding a split binding repeats the action; add a repeat check in handlers that must not repeat (the handler does not see the event; use a `window.observe_keystrokes`/interceptor or ignore).
- `cx.observe_keystrokes(|&KeystrokeEvent { keystroke, action: Option<Box<dyn Action>>, context_stack }, window, cx|)` (app.rs:1628, struct app.rs:2332) fires after an action ran (window.rs:3836-3846).

### 1.7 M1 key handling and what must change

Current (crates/cmux-app):
- `keys::BINDINGS` is a hard-coded `(&str, AppAction)` table (keys.rs:15-20); `keys::binding()` string-matches `chord(ks)` (keys.rs:22-45).
- `TerminalView::key_down` (terminal_view.rs:272-303) first checks `keys::binding`, records `bound_keys`, runs Copy/Paste and `stop_propagation`s; then swallows every Super chord; then encodes everything else for the PTY and stops propagation if bytes came out. So today the terminal consumes keys *in a listener that runs after the keymap*, but there is no keymap, so no gpui action ever runs.
- `key_up` (terminal_view.rs:305-314) drops releases for keys in `bound_keys` or with Super.

Order matters: keymap actions run **before** `on_key_down` listeners (window.rs:3834 vs :3848), so the terminal does not pre-empt actions. A bound chord never reaches `key_down` unless its handlers all `propagate()`.

Required changes:
1. Define actions (`Copy`, `Paste`, split/tab/focus/resize...) and bind them from a table loaded by `cmux-config` (1.5). Delete `AppAction`, `BINDINGS`, `binding()`, and the early branch in `key_down` (terminal_view.rs:273-280). Register Copy/Paste as `.on_action` on the terminal div (terminal_view.rs:353-359), with `cx.propagate()` when there is nothing to do.
2. The Super catch-all (terminal_view.rs:285-287) stays: unbound Super chords must not become terminal input. It also keeps `replay_pending_input` from inserting `key_char`.
3. `bound_keys` is no longer filled (key_down is skipped for bound chords), so the key-up suppression (terminal_view.rs:306) loses its source. Options: in `key_up`, ask the keymap: `cx.key_bindings().borrow().bindings_for_input(&[ev.keystroke.clone()], &window.context_stack()).0.is_empty()` (keymap.rs:142, window.rs:4196), or record from `cx.observe_keystrokes` when `event.action.is_some()`. The loss only matters when an app negotiates kitty event types (otherwise `encode_key(.., Release)` is empty, terminal_view.rs:309-313), but remapped non-Super bindings (ctrl-shift-c) make it reachable.
4. `PtyEvent::Exited => cx.quit()` (terminal_view.rs:191) must become an emitted event (`impl EventEmitter<TerminalEvent> for TerminalView`, parent `cx.subscribe(&terminal, ..)` which holds the parent weakly, context.rs:98) so the pane closes the tab.
5. Mouse handlers should ignore events while a divider/tab drag is active (1.2 B), or use route A.
6. `window.set_window_title` in `render` (terminal_view.rs:347-352) must only run for the active tab of the active pane.
7. Keep the `Terminal` key context; add `Pane` and `Workspace` contexts on the wrapper divs so config can target them.

## 2. Zed reference (`zed@69e2130 crates/workspace/src/pane_group.rs` unless noted)

All adaptable under GPL-3.0-or-later; add the attribution header M1 files use. Zed's `Entity<Pane>` becomes our pane id or `Entity<PaneView>`; the tree itself should live in `cmux-core` as pure data (spec) with a view layer reading it.

Data model (lines 29-45, 241-245, 523-530):
- `PaneGroup { root: Member }`, `enum Member { Axis(PaneAxis), Pane(..) }`, `PaneAxis { axis, members: Vec<Member>, flexes: Vec<f32>, bounding_boxes: Vec<Option<Bounds>> }`. Flexes are *weights summing to `members.len()`* (default 1.0 each); size of child i = `container * flexes[i] / len` (`PaneAxis::load` re-normalises bad data, :542-557).
- `split` (49-67, `PaneAxis::split` 560-590): same-axis split inserts the new pane next to the old one (`direction.increasing()` => idx+1) and resets all flexes to 1; different-axis split replaces the leaf with `Member::new_axis(old,new,dir)` (418-433; Up/Left put the new pane first). `insert_pane` and `remove` both reset flexes to equal (:592-596, 612-652). cmux keeps ratios; decide whether to preserve instead of reset (Zed's reset-on-change is the simple, tested behaviour).
- `remove` (136-147, 612-652): remove leaf; if its axis is left with one member, return that member so the parent replaces the axis with it (collapse). Zed does not merge a collapsed same-axis child into its parent; normalise in `cmux-core` if cmux does.
- `swap` (773-786), `reset_pane_sizes` (654-661), `first_pane/last_pane`, `panes()` (collect leaves in order).
- Constants: `HANDLE_HITBOX_SIZE = 4.0`, `HORIZONTAL_MIN_SIZE = 80.`, `VERTICAL_MIN_SIZE = 100.` (21-23), `DIVIDER_SIZE = 1.0` (990). Compare with cmux's Swift split view numbers when sizing.

Resize maths:
- Pointer drag, `PaneAxisElement::compute_resize` (1053-1148): delta = `(mouse - child_start).along(axis) - size(ix)`; flex change = `delta / container`; moves flex between `ix` and `ix+1`, clamps both to `min_size`, and carries any leftover delta on to the next neighbour in the drag direction (successor iterator). Exits early if the target is already below min.
- Keyboard resize, `PaneAxis::resize` (663-771): same clamp maths, recurses to find the nearest ancestor axis of the requested direction; last member shrinks by growing its predecessor. Useful for cmux's resize-split shortcuts.
- Double-click on a handle resets that axis to equal flexes (`click_count >= 2`, 1388-1396).

Rendering (module `element`, 968-1449): custom `Element` `PaneAxisElement` with children `AnyElement`s.
- `request_layout`: `Style { flex_grow 1, flex_shrink 1, flex_basis relative(0), size 100%x100% }` via `window.request_layout(style, None, cx)` (1199-1214).
- `prepaint`: for each child, size = `bounds.size.apply_along(axis, |_| space_per_flex * flex).map(round)`, then `child.layout_as_root(size.into(), ..)`, `child.prepaint_at(origin, ..)`, push `Some(child_bounds)` into the shared `bounding_boxes`, advance origin; then `layout_handle` per boundary (1151-1177): hitbox of 4 px centred on the boundary (`HitboxBehavior::BlockMouse`) and a 1 px divider rect right after the child.
- `paint`: paint children, optional inactive-pane overlay (`paint_quad(gpui::fill(..))`) and active border (`gpui::quad(.., border, color, BorderStyle::Solid)`), then per handle: cursor style (set_window_cursor_style while dragging, else hitbox cursor), `paint_quad(fill(divider_bounds, color))`, down/move/up listeners as in 1.2 A (1292-1435). Mouse-up clears the drag index.
- Gpui calls to keep: `Along::along/apply_along`, `Axis`, `Bounds::{union,contains,center}`, `window.with_element_state`, `insert_hitbox`, `on_mouse_event`, `paint_quad`, `set_cursor_style`.

Directional focus (203-233, 788-823):
- `find_pane_in_direction(active, dir)`: take the active pane's bounding box (from the last prepaint), choose a probe point = cursor pixel position if inside the box else the box centre, step `HANDLE_HITBOX_SIZE` outside the box in `dir` along the axis keeping the other coordinate, and return `pane_at_pixel_position(point)` (recursive search of `bounding_boxes`). It returns `None` at the window edge (Zed has `move_to_border`, :89-134, for wrap/overflow).
- cmux-linux can compute the same rectangles purely from the tree + window size (flex maths above), which is unit-testable in `cmux-core` and does not depend on a render having happened. For the probe point use the active pane's cursor cell (M1 has `cursor_cell` + `Geometry`, terminal_view.rs:82,42) or the box centre. Check what the Swift app does when several panes touch the edge (bonsplit), the Zed rule picks the pane under the probe.

Tabs (`crates/workspace/src/pane.rs`): `render_tab_bar` (3026-3190): start/end slot buttons, a scrolling `h_flex` with `overflow_x_scroll().track_scroll(&ScrollHandle)`, then a trailing flex-grow drop target; `render_tab` (2521-2700) for tab elements; `DraggedTab` + `Render` (449, 4189); drop move/clone in `handle_tab_drop` (3251) via `move_item`; `Pane::render` wires `key_context("Pane")`, `track_focus`, and `.on_action(cx.listener(..))` per action (3685-3830). The pane body is `flex_1().relative().overflow_hidden()` holding the active item view.

## 3. PTY shutdown (`crates/cmux-term/src/pty.rs`)

Current behaviour:
- The reader thread owns `reader` (a `dup` of the master from `try_clone_reader`, `portable-pty-0.9.0/src/unix.rs:352-355`: `PtyFd(self.fd.try_clone()?)`) and does a blocking `read` (pty.rs:147). `PtyFd::read` maps EIO to `Ok(0)` (unix.rs:93-105), so EOF/EIO ends the loop and sends `Exited` (pty.rs:163-165).
- `Session::drop` only sets `closed` (pty.rs:205-210) and the `ChildGuard` SIGHUPs the *shell's process group* (pty.rs:49-52). A `setsid`'d grandchild is outside that group and still holds the slave, so the master never reports hangup and the reader blocks forever.
- Leak chain: reader thread -> `shared: Arc<Mutex<Term>>` -> `Term` holds a clone of the writer `Sender` (pty.rs:121) -> the `pty-writer` thread `for bytes in rx` never ends -> its `UnixMasterWriter` dup (unix.rs:357-363,389-405) keeps the master open. Dropping `Session.master` (pty.rs:29) does not help because the dups keep the open file description alive. Throwaway Python check (not in repo): after closing the original master fd, a `read` blocked on a dup stayed blocked; `poll` on the master returns `POLLHUP` (+ `read` -> EIO) once the slave is closed, and a `poll` on `[master, pipe]` returns as soon as the pipe is written.
- `portable-pty` exposes what we need: `MasterPty::as_raw_fd(&self) -> Option<RawFd>` (lib.rs:114, unix.rs:366), `try_clone_reader` (lib.rs:97), `take_writer` (lib.rs:102, once only, unix.rs:357-361), `process_group_leader` (lib.rs:107). The reader is a boxed `Read`, so its fd is not directly pollable; poll a `dup` of `as_raw_fd()` instead.

Minimal design (poll + wake):
1. In `Session::spawn`: `let (wake_rx, wake_tx) = std::os::unix::net::UnixStream::pair()?;` (safe std; no pipe unsafe) and own a private duplicate of the master fd for polling: `OwnedFd` from `BorrowedFd::borrow_raw(master.as_raw_fd().ok_or(..)?).try_clone_to_owned()?` (the one `unsafe` borrow; do it before `master` is moved into `Session`). `libc` is already a dependency (Cargo.toml).
2. Reader loop: `libc::poll` on `[master_dup POLLIN, wake_rx POLLIN]` with timeout -1. If the wake fd is readable/hung up: `return` without sending `Exited` (the existing `reader_closed` check covers a racing event). If master reports `POLLIN | POLLHUP | POLLERR`: do `reader.read(&mut buf)` as now (it will not block; EIO -> `Ok(0)` -> `Exited`). Retry on `EINTR`.
3. `Session` keeps `wake_tx: UnixStream` as a field; `Drop` sets `closed` and either writes one byte or just drops the stream (peer close makes `wake_rx` readable with `POLLHUP`); no explicit write needed.
4. After the reader returns it drops `reader`, `shared` (Term), and the event closure; `Session.term`/`writer` are dropped with the session, so the last `Sender` goes away, `pty-writer` exits, `UnixMasterWriter::drop` runs (it writes `\n` + VEOF into the pty, harmless after the SIGHUP, unix.rs:393-405) and closes. All master fds are then closed, so the kernel hangs up the pty: the setsid grandchild's next tty read/write gets EIO/SIGHUP semantics. No thread, fd or `Term` survives the pane.
5. Alternative without a wake fd: `poll` with a 100-250 ms timeout and check `closed` each wake. About 4-10 idle wakeups per second per pane; not recommended with many panes.
6. Not enough: only dropping the master (see leak chain), or making the master non-blocking (`O_NONBLOCK` is on the shared open file description, so it also affects the writer thread's blocking `write_all`).
7. Also decide in M2: panic in `feed` kills the reader without `Exited` (STATUS.md M6 item); with the poll loop, wrapping `feed` in `catch_unwind` or a drop guard that sends `Exited` fits here.
8. `Session::resize` locks the `Term` on the GUI thread (STATUS.md); with N panes each resize during a divider drag runs once per pane per frame at most (resizes only when `Geometry::needs_resize`, terminal_view.rs:62).

Strong vs weak handles in M1 callbacks:
- PTY event closure (terminal_view.rs:111-113) captures only the mpsc `Sender`; no entity. OK.
- `pty_task`/`blink_task` use `cx.spawn(async move |this, cx|)` where `this` is a `WeakEntity` (context.rs:237-244) and exit when `update` returns `Err` (terminal_view.rs:124-129,150). OK; tasks are stored in `_tasks` and cancelled on drop (terminal_view.rs:182).
- `cx.on_focus_in` / `cx.on_blur` / `cx.subscribe` / `cx.observe` capture `weak_entity()` (context.rs:63-120, 532-640). OK. `cx.listener` downgrades (context.rs:256). `cx.processor` and `cx.entity()` captured in closures are **strong** (context.rs:264-271); do not use them in long-lived callbacks.
- `TerminalElement::new(cx.entity())` (terminal_view.rs:369) holds a strong `Entity` for one frame, and `window.handle_input(.., ElementInputHandler::new(bounds, self.view.clone()), cx)` (terminal_element.rs:406-409) stores a strong clone in the next frame's input handlers while the view is focused (window.rs:3410). Both are transient (replaced each frame), so a closed pane is released one frame later. No cycle found. `main.rs` registers no callbacks. For M2: when a pane/tab is removed, drop all `Entity<TerminalView>` strong refs (tree, tab lists, drag payloads) so `Session::drop` runs; use `WeakEntity` in drag payloads and in any divider/tab closure registered with `window.on_mouse_event`.
